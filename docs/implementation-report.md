# 分阶段实施与验收报告

这是上一阶段的历史记录。后续更严格的实际生成质量判断见[质量评测报告](quality-assessment.md)。

基线提交：`d414605`。保留原有两项 Skill 和全部 162 个随包 feature 文件，未整体重新生成 Skill。公开能力仍以 NebulaGraph 5.3.0 用户文档为准；根据任务所有者确认，提供的 5.3.2 服务端作为兼容验证环境使用。

## 阶段 1：审查与基线

修改前完成 [问题清单与优先级](audit-2026-10-23.md)。识别 CALL 路由冲突、长参考检索成本、仅函数名称审计、缺少自然语言/模型/性能评测，以及没有测试门禁的发布流程。

基线实跑：3 项单元测试、196 个正例代码块静态审计、70 个本地链接、4 个既有生成目录与原始文档的一致性检查、3 个压缩包验证均通过。它们不能证明模型生成正确性，后续单独建立了评测。

## 阶段 2：有针对性的 Skill 改进

- 统一查询/过程边界：已有签名的 CALL/YIELD 检索归查询；定义、管理、签名设计、控制流与状态算法归过程。
- 增加标准库实现的自包含检索/检查脚本、短最终检查表和纠错契约。函数按精确名称检索；主题先返回精确标题，正文提及显式按需加载，截断有续读指针。
- 保留完整函数/语法目录和人工专题参考；新增从文档提取的 224 个保留关键字，解决别名引用问题。关键字清单不能授权未文档化能力。
- 修复 `{0}` 报错时擅自扩大到 `{0,1}` 的原有建议；纠错必须保持跳数、重复、NULL、作用域、返回列及副作用意图。
- 增加普通函数参数数量、接收者、环境与部分类型检查，以及 PER NODE/PER PATH 内 RETURN、Analytics 普通 MATCH RETURN 等已确认边界。

静态脚本明确标注其并非完整 GQL 解析器或类型系统；复杂签名/接收者仍需针对性核对。

## 阶段 3：回归、反例和模型评测

[用例集](../evals/cases.json)有 37 个自然语言案例，覆盖基础查询、路径、聚合、分页、Cypher/nGQL 迁移、过程、错误修复、负例和边界；另有 [16 个路由案例](../evals/triggers.json)。导出给生成模型的内容不包含参考答案或评分断言。

评测接收真实模型输出，拒绝缺失、重复和未知案例 ID。42 项单元/对抗测试覆盖函数/类型/语法边界、执行限制、重复/NULL/排序/精度、错误修复、增量更新和打包。独立审查发现的错误分组、OPTIONAL 丢失 NULL、错误相关变量、更新错误节点、修改错误过程和伪造负例说明均已增加区分性检查。

独立生成与评分发现并修正了评测自身的问题：过程管理提示缺少签名、参考答案虚构起点过滤、Analytics 参考误用普通 MATCH，以及把有效证据措辞和 RETURNS/PARTITION 误判为错误。没有改写模型输出以迎合参考答案。

| 实测项目 | 原版 | 最终改进版 |
| --- | ---: | ---: |
| 保存的生成结果通过静态契约 | 35/37 | 37/37 |
| 只读数据库语法与结果比对 | 11/12 | 12/12 |
| 保存的路由选择 | 16/16 | 16/16 |

原版两项静态错误为未引用保留字 BIG，以及 PER NODE 内使用 RETURN；前者同时在数据库验证中失败。参见 [原版评分](../evals/reports/model-baseline.json)、[当前评分](../evals/reports/model-current.json)、[真实生成记录](../evals/observations/README.md)。

每版完整测试为一个独立代理批次；虽然要求每题独立理解，仍存在共享上下文和顺序影响。精确模型标识及 token 遥测未由工具提供。以上是本组案例的观测，不是总体准确率、统计显著性或宿主自动触发率。

## 阶段 4：在线正确性与性能

[在线记录](../evals/reports/database-current.json)覆盖 12 个无业务图依赖的只读案例：先由服务端 EXPLAIN，再执行并比对列、值类型、重复、NULL、排序和大整数。三个纠错案例先复现原错误码，再验证修复结果；错误码分别为 NR002、42N47、42001。仅固定、已审查的原错误语句允许进入诊断通道。没有执行业务写入或随包 feature 的建图/清理操作。

[性能记录](../evals/reports/database-fixtures.json)使用不可变列表进行等价性检查、预热、6 对交替执行和两个 PROFILE 树，报告中位数、范围和 p95；每次运行都核对完整结果。语法位置改变没有被当作性能最优证据。

[六类图性能模板](../evals/performance.json)覆盖超级节点、变长路径、中间结果放大、OPTIONAL MATCH、相关子查询和分页。运行器支持显式指定已有隔离图及快照/规模/索引设置说明后进行只读对比，设置请求超时和结果预算，失败或溢出不生成截断后的等价结论。**本轮没有运行代表性图工作负载或 Analytics 过程**：未提供满足模板要求的图 Schema/快照。因此不声称业务图加速、完整过程运行验收或业务 SLA。

## 阶段 5：上下文、增量维护与发布门禁

[上下文观测](../evals/reports/context.json)：完整 37 题批次的读取量从 146,977 字节增至 163,519 字节，没有证明整体下降；单独迁移请求从 36,102 降至 35,220 字节（约 2.44%），耗时反而增加。它们是参考读取字节，不是模型 token。测量还发现主题检索排序问题，随后增加了精确标题优先和显式 `--all-matches`；RETURN 默认检索现在返回 570 字符的两个直接章节，而其余 129 处正文提及保留为按需读取。后续更广泛上下文收益仍需更多独立样本。

增量追踪记录 218 个文档页面、243 个上游 feature 和 1,335 个版本固定的相关源码文件。文档变化映射到案例，代码/feature 变化保守选择全套评测；新增 feature 也会检测。刷新只更新内容有变化的 6 个生成文件；人工参考、Skill 指令和用例不被覆盖。实际检查得到零源变化，四个原始目录保持原内容，新关键字目录与用户文档一致。

GitHub Actions 对所有 PR、main 推送及手动运行执行静态审计、42 项测试、参考/真实保存输出回归、路由检查、打包与解压后独立运行检查。发布依赖验证任务成功，只使用该任务上传的压缩包；PR 无写权限，手动版本通过环境变量传递并校验。已本地验证 YAML 与同一门禁命令，**未推送或触发远端 Actions，也未发布**。

## 阶段 6：自包含与交付

两项独立 ZIP 和合并 ZIP 均校验内容、路径、链接及 feature 索引。独立包在临时目录以 Python 隔离模式运行检索与 lint 成功，不依赖原始代码、手册、构建目录或仓库级评测脚本。

运行方法见 [维护指南](maintenance.md)。`dist/evaluation-review.html` 为 skill-creator 生成的交互评审文件，展示两版逐题输出、检查证据和评分。没有提交、推送、发布、业务图写入或凭据入库。
