# 判断 Skills 是否生成得好

旧的 37/37 是静态契约通过数，不能用作生成正确率。本轮对抗检查找到 18 条不应判为通过的输出。旧指标保留为诊断，不作为质量结论。

## 判断单位与证据

- **一个案例**包含自然语言、完整 Schema/环境/参数契约和多个隐藏输入实例；同一生成结果必须在全部实例上正确。不能只在一个巧合的数据集上正确。
- **一个独立尝试**由新上下文生成，不能看到参考答案、预期行、评分条件、别人的输出或上次报错。调试重试与首次成功分开记。
- **一次评测版本**冻结 Skill、案例、运行器和模型输出摘要；源变化后旧记录不能代表当前版本。模型标识/采样设置未知时明确记录，不能跨模型推广。
- **语法/类型**由数据库实际解析与执行确认；**语义**以独立 Python 数据模型的预期结果为准。静态脚本仅作能力/危险操作诊断。
- 保持列名、值类型、NULL、重复次数、路径集合和必要排序；命名过程生命周期、Database 过程体、Analytics 过程体分别计分。
- 用故意错误的变体检验评测器：错起点、反方向、错误去重、NOT EXISTS、路径唯一性、累计值和分支边界必须能被数据区分。评测器未杀死的错误变体会阻止其对应案例被用作充分证据。

## 预先固定的结论规则

对声明覆盖范围内的案例，要求每题至少两次独立生成、每次全部隐藏输入正确，且没有未解决的高风险错误，才报告“通过本套范围验收”。同一题的多个数据实例不能伪装成多个独立生成样本。报告首次成功率、重复一致性、按能力分组的失败和区间，不将这个有限题集称为总体准确率。

缺案例、缺运行证据、未执行的语义类别、陈旧源摘要、缺重复或仍有未杀死错误变体时，结论为“证据不足”，不按零失败计算为通过。已执行并产生错误结果的项目为“未通过”，不是“证据不足”。负例/拒绝类另行评定，不能用大量简单拒绝题抬高执行正确率。

开发集可用于修改 Skill；留出题在源冻结后才生成和评分，首次留出结果永久保留。根据留出失败再改动后，它已成为开发证据，下一次正式验收需要新的留出题或明确标为重复回归。

## 安全执行与边界

普通查询使用自有随机命名的内存临时图和纯合成数据；复用已有样例 Graph Type 的 Schema，不读取业务节点、不创建或修改持久业务图。临时图并非会话自动清理，执行器必须显式清理自己成功创建的精确名称，清理失败使本轮验收失败。

Database 控制流以无副作用内联过程执行；Analytics 在自有临时图上验证。只允许明确受控的本地变量/聚合器赋值，禁用模型提供的图切换、DDL、文件/网络导入导出、命名过程调用及业务数据修改。未知结构标为执行器尚不支持，不能冒充已执行。

`dry_run` 不是命名过程 DDL 的安全沙箱：文档明确 CREATE GRAPH TYPE/GRAPH/PROCEDURE 仍实际执行。仅执行过程体不能证明命名签名、默认参数、重载、权限或生命周期全部正确。请求超时也不等于服务器循环已被终止；未经确认终止边界的循环不能自动执行。

## 可复现的使用方式

以下命令从仓库根目录执行。离线验证只需 Python 标准库；在线步骤需要安装了 `nebula5_python` 的 Python 环境，并私下设置 `NEBULA_ADDRESS`、`NEBULA_USER`、`NEBULA_PASSWORD`。

```sh
# 只导出公开题面与版本摘要；不包含输入图、答案或评分实现
python3 scripts/quality/run.py --export > public-prompts.json

# 对每题启动独立上下文两次，保存单独的 JSON 文件到 attempts/
# 字段：case_id、attempt(1/2)、query、skills_sha256、notes
# 生成器只读取所选题面及对应 src Skill，不能读取 evals/ 或 scripts/quality/

# 先确认独立 oracle 能通过正确程序、拒绝语义错误变体
python3 scripts/quality/calibrate.py --report dist/quality-calibration.json

# 再执行真实模型输出；不自动改写候选代码
python3 scripts/quality/run.py --outputs attempts/ --report dist/quality-model-run.json

# 无需数据库，重算保存的实际合成行、类型、重复/顺序与质量结论
python3 scripts/quality/verify.py \
  --report dist/quality-model-run.json \
  --calibration dist/quality-calibration.json \
  --outputs attempts/
```

默认复用已有的 `basketballplayer_type` Schema；可用 `--graph-type` 指定兼容的现有类型。需要 player(id STRING 主键,name STRING,age INT64 可空) 和 follow(player→player,degree INT64 可空且允许平行边)。运行器不创建持久 Graph Type；Schema 不兼容或夹具回读不匹配时失败，不改造业务类型。

输入包含平行边、环、NULL、孤立点、逆向/自环图、空图和不同长度业务 ID；Python oracle 不通过解析参考 SQL/GQL 得到答案。执行器回读种子图，确认实际节点/边及属性与输入一致，再执行候选。只有已证明有界的计数 WHILE 能自动运行；其它循环或不在受控子集内的语句为“未验证”。

每条记录保留实际结果的类型标记表示、服务端状态、清理结果和输出摘要。离线 verifier 重新计算期待结果和分组结论，检查完整输入实例、两次生成、原始输出及源版本，而不是相信 `passed` 字段。它还能发现改动过的结果行、遗漏实例或陈旧的 oracle 校准。

`evals/quality/generation-manifests.json` 保存生成时完整源文件摘要。整个包变化时，只有被调用的**整项 Skill 目录逐文件完全相同**，才允许复用该项 Skill 的原始生成；另一项 Skill 的修改不能伪装成未变化。原始输出的版本字段不会被重写。题集或执行器变化必须重跑校准与执行评分。

`check_all.py` 和 GitHub Actions 现在也执行保存证据的离线重算。三个声明已覆盖的子范围必须全部通过，缺失/陈旧/失败会阻止门禁；总报告仍明确保留命名生命周期和分布式 Analytics 的“证据不足”。这不是把未知范围判成通过。

本轮使用独立代理上下文及只读指定输入路径的约束隔离生成材料，没有声称已施加操作系统文件系统沙箱。精确模型快照与采样参数未由代理工具提供，记录为会话继承；未来跨模型比较应额外记录这些信息。
