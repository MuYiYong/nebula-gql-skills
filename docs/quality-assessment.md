# 当前 GQL Skills 的质量判断

结论：**在本套明确覆盖的范围内，查询、Database 过程体及本地临时图匹配计算已达到验收标准；不能据此笼统保证所有 GQL/Procedures 都能很好生成。** 命名过程生命周期与分布式 Analytics 仍缺乏执行证据。

这次已建立可重复运行的判定体系，并用实际失败修正了 Skills。此前的 37/37 静态得分不能承担这个结论：独立对抗检查找到了 18 条不应判为通过的结果，涉及错误方向/起点、反转 EXISTS、丢失重复行、错误过程计算以及未解析调用。[原始反例与评分](../evals/quality/evidence/static-false-positives.json)完整保留。

## 实际评测结果

13 个案例，每题两次独立上下文生成；同一候选在多组隐藏数据或参数边界上执行。输入包含并行边、环、自环、NULL、孤立点、空图、重复分数和不同长度业务 ID。使用独立 Python oracle 比较实际结果，不把参考语句字符串相似度当作语义正确。

| 范围 | 独立生成通过 | 输入执行比对 | 当前结论 |
| --- | ---: | ---: | --- |
| GQL 图查询：OPTIONAL、分组、TRAIL/ACYCLIC、相关反存在、稳定分页 | 12/12 | 48/48 | 通过本套范围验收 |
| Database 过程体：有界 WHILE、分支、重复贡献合并 | 6/6 | 22/22 | 通过本套范围验收 |
| 本地临时图匹配计算：点绑定聚合、长名 SetAgg、入边累计、STRING 聚合 | 8/8 | 22/22 | 通过本套范围验收 |
| 命名过程默认参数、重载、权限和创建/变更/删除生命周期 | 未执行 | — | 证据不足 |
| 分布式 Analytics | 端点不支持 | — | 证据不足 |

共 **26/26 次独立生成、92/92 组输入比对通过**。在此前首轮实测中，本地匹配计算有一次错误使用 `NEXT`，整体为 23/24；原始失败没有被修改或删掉。[首轮记录](../evals/quality/evidence/iteration1/model-run.json)与[最终完整记录](../evals/quality/evidence/current/model-run.json)可逐项对照。

最终题集新增了此前未使用的字符串聚合留出题。过程参考中还发现两处遗漏的旧规则，清除后全部过程结果重新生成。查询 Skill 未发生对应变化的 8 份结果，仅在完整目录逐文件摘要相同的证明下复用；原版本字段保留。不是把旧结果改标为新版本。

在评测模型之前，13 个参照程序全部正确，13 个故意写错的语义变体均被真实结果区分。校准和实际结果均保存了可离线重算的类型标记行数据。[校准记录](../evals/quality/evidence/current/calibration.json)、[独立 oracle](../scripts/quality/oracles.py)和[证据重算器](../scripts/quality/verify.py)可用于检查结论。

## 已优化的具体问题

1. **过程阶段错误使用 NEXT**：本轮真实生成导致服务端 `42001`。增加顺序过程阶段说明与 `compute-next` 检查，保留普通 `RETURN ... NEXT ...` 查询管线；修复后独立重生成通过。
2. **NODE_GLOBAL 错误迁移为 ACYCLIC**：全局访问集合与每条路径的节点不重复不是等价语义。现在要求保留 visited 与遍历/路径选择契约，不再机械替换。[APOC 官方唯一性定义](https://neo4j.com/docs/apoc/current/overview/apoc.path/apoc.path.expandConfig/)
3. **分数贡献被 UNION 去重**：明确接受按字段相加时改用 UNION ALL；修复与规则冲突的全文检索示例，并说明跨数据库排名不能默认等价。
4. **误禁 Database 过程里的 USE**：恢复公开文档允许的形式；默认继承调用方图与禁止图选择不再混为一谈。
5. **错误的聚合器限制**：删除已在 5.3.0 发布前修复的 SetAgg 15 字符名称限制；恢复公开支持的 SumAgg<STRING>。新留出题实跑了字符串聚合，未使用数值计数代替。
6. **能力目录漏掉 Database 范围**：成员方法按 Database/Analytics 各自公开文档生成环境信息；补入 Database 本地临时图 match-compute 语法。没有凭运行成功引入未文档化能力。

这些变更保留了原有 Skill 与人工参考，只修改对应规则和示例。公开能力基线仍为 5.3.0，按用户确认将提供的 5.3.2 服务端视作兼容环境。

## 结论的边界

- 这是 13 个有针对性的案例，不是随机抽取的大规模业务题库。报告中的 Wilson 区间只是描述性参考；重复输入和第二次生成不会伪装成更多独立案例，也不能证明总体 95% 正确率。
- 图算法覆盖的是局部匹配计算和聚合，不包含完整 BFS/SSSP/PageRank 等算法质量验收；图性能与业务 SLA 也不在这次正确性结论内。
- 该测试端点对分布式临时图返回 NI000，见[能力探测记录](../evals/quality/evidence/runtime-capabilities.json)。Database 本地匹配计算有单独的公开文档依据，不能将其成功外推到分布式 Analytics。
- 本次没有创建持久命名过程。过程体成功不能证明签名、重载、ACL、默认参数或生命周期都正确；`dry_run` 会实际执行部分 DDL，不能充当这类操作的安全沙箱。
- 没有可靠证明任意同步 WHILE 可由超时终止，所以执行器只自动运行经检查有界的循环。

运行器只使用自有随机命名内存图和合成数据，没有读取业务节点或修改持久图类型。首轮校准中清理语句拼写错误产生的 66 个自有临时图已逐一成功清除，随后修正为 `DROP GRAPH #精确名称` 并增加清理失败立即停止的测试。最终校准与生成评测的清理均成功。

## 后续如何判断一个新版本

按[判定方法与命令](quality-method.md)冻结输入及源版本、独立生成、校准 oracle、执行和离线重算。新增业务能力时补充能区分错误实现的数据与变体；源或题集变化导致旧证据失效时不能沿用旧的绿色得分。当前 CI 对声明已覆盖范围的保存证据执行重算，未知范围仍明确显示“证据不足”。

最终本地门禁：60 项测试、六个生成目录与原始文档一致性、保存语义证据的独立重算、静态审计、压缩包及解压独立运行检查全部通过。逐题比较可打开 `dist/quality-review.html`。
