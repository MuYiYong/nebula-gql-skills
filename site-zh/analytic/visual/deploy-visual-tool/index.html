    部署悦数图分析控制台¶

    悦数图分析控制台用于可视化运行悦数图分析作业。本文介绍如何在 K8s 集群中部署悦数图分析控制台。

    部署悦数图分析控制台包含以下核心组件：

    • 悦数图数据库 Operator（nebula-operator）：用于管理 Meta 服务。
    • 悦数图分析 Operator（analytics-operator）：用于管理悦数图分析作业。
    • kube-prometheus-stack：用于监控指标采集。
    • analytics-server：用于提供可视化 UI 和 RESTful API。

    前提条件¶

    在操作前，请确保满足以下要求：

    • 一个 K8s 集群，版本 >= 1.29.0。
    • 已安装 Helm，版本 >= 3.2.0。
    • 已安装 CoreDNS，版本 >= 1.10.0。

    • 已获取并解压以下 Helm chart 安装包：

      • nebula-metad
      • nebula-operator
      • analytics-operator
      • analytics-server
    • 了解悦数图数据库的架构和组件。

    步骤一、部署依赖组件¶

    1. （可选）部署 Meta 服务
    2. 安装悦数图分析 Operator
    3. 安装 kube-prometheus-stack

    步骤二、安装 analytics-server¶

    1. 创建命名空间：

      kubectl create namespace graph-system

      所有 analytics-server 资源都将位于命名空间graph-system中。如果跳过此步骤，将使用默认命名空间default。

    2. 创建用于从私有镜像仓库拉取 analytics-server 镜像的 Secret：

      kubectl -n graph-system create secret docker-registry SECRET_NAME \
--docker-server=DOCKER_REGISTRY_SERVER \
--docker-username=DOCKER_USER \
--docker-password=DOCKER_PASSWORD
      • graph-system：存储 Secret 的命名空间。
      • SECRET_NAME：Secret 的名称，例如vesoft。
      • DOCKER_REGISTRY_SERVER：私有仓库的服务器地址，例如reg.example-inc.com。
      • DOCKER_USER：登录镜像仓库的用户名。
      • DOCKER_PASSWORD：登录镜像仓库的密码。

    3. 在解压后的目录analytics-server的父级目录中，安装 analytics-server。您可以在安装的时候通过--set参数自定义 Helm chart 的配置。具体操作，请参见 Customizing the Chart Before Installing。例如：

      helm install analytics-server analytics-server/ --set imagePullSecrets[0].name="vesoft" -n graph-system
      • analytics-server：Helm release 的名称。
      • analytics-server/：Helm Chart 的路径。
      • graph-system：部署的命名空间。
      • vesoft：上一步创建的 Secret 名称。如果不需要从私有仓库拉取镜像，可以省略此参数。

      关于可配置的参数，请参见下文的 analytics-server 安装配置参考。

      返回：

      NAME: analytics-server
LAST DEPLOYED: Tue Jun 17 18:11:01 2025
NAMESPACE: graph-system
STATUS: deployed
...

    4. 查看已安装的 Helm release：

      helm list -n graph-system

      返回：

      NAME                    NAMESPACE               REVISION        UPDATED                                 STATUS          CHART                   APP VERSION
analytics-server        graph-system            1               2025-11-19 16:25:11.871080907 +0800 CST deployed        analytics-server-1.0.0  1.0.0

    步骤三、配置运行时设置¶

    analytics-server 安装后会自动创建名称为<helm_release_name>-config的 ConfigMap，其中<helm_release_name>为 Helm release 的名称，用于存储运行时配置。例如，若 Helm release 的名称为analytics-server，则运行时配置的 ConfigMap 名称为analytics-server-config。

    安装 analytics-server 后，需要修改默认的运行时配置。操作步骤如下：

    1. 创建 Secret。

      Caution

      请确保以下 Secret 均在命名空间nebula-analytics-job中创建，否则会导致运行时配置无法生效。

      • 创建用于从私有镜像仓库拉取 Analytics 服务镜像的 Secret，用于下步中Job.ImageSecret的参数设置。示例命令：

        kubectl -n nebula-analytics-job create secret docker-registry vesoft \
  --docker-server=DOCKER_REGISTRY_SERVER \
  --docker-username=DOCKER_USER \
  --docker-password=DOCKER_PASSWORD

      • （可选）创建用于访问云存储服务的 Secret。

        若悦数图分析服务需要访问云存储，例如 AWS S3，用于数据输入或输出，需创建相应的 Secret。示例命令：

        kubectl create secret generic <secret_name> --from-literal=<access_key_name>=<access_key_id> --from-literal=<secret_key_name>=<secret_access_key> -n nebula-analytics-job
        • <secret_name>：Secret 名称。例如，aws-cred。
        • <access_key_name>：Secret 中的键名，用于存放访问密钥 ID。例如，access_key。
        • <access_key_id>：访问密钥 ID。
        • <secret_key_name>：Secret 中的键名，用于存放秘密访问密钥。例如，secret_key。
        • <secret_access_key>：秘密访问密钥。

        创建 Secret 后，其可在用于运行悦数图分析作业的过程脚本中按格式${.secretRef.<secret_name>.<access_key_name>}:${.secretRef.<secret_name>.<secret_key_name>}被引用。

        例如，若引用用于访问 AWS S3 的aws-cred Secret，则格式为s3://${.secretRef.aws-cred.access_key}:${.secretRef.aws-cred.secret_key}@<aws_bucket>/<file_path>。

    2. 编辑运行时配置的 ConfigMap，进行以下配置：

      • Meta 服务连接配置（Metad）
      • 图分析任务运行配置（Job）
      • 可视化页面用户可选的计算资源配置选项（ComputeResources）
      • Prometheus 监控集成配置（Prometheus）

      编辑命令如下：

      kubectl edit configmap analytics-server-config -n graph-system

      示例配置如下：

      # 配置名称，用于标识该配置文件
Name: analytics-api
# 服务监听的网络地址。0.0.0.0 表示监听所有 IPv4 接口
Host: 0.0.0.0
# 服务监听的端口号，默认为 7006
Port: 7006
# 单次请求允许的最大字节数（单位：字节），此处为 1 GB（1024^3）
MaxBytes: 1073741824

# 调试相关配置
Debug:
  # 是否启用调试模式（如返回详细错误信息、开启开发日志等）
  Enable: false

# 日志配置
Log:
  # 日志输出模式：file（写入文件）或 console（标准输出）
  Mode: file
  # 日志级别：debug / info / warn / error
  Level: info
  # 日志文件保留天数（自动清理超过此天数的日志）
  KeepDays: 7

# API 请求超时时间（单位：毫秒），此处为 20 秒
Timeout: 20000

# 数据库连接配置，用于存储悦数图分析控制台的元数据
# 目前仅支持 MySQL 和 SQLite3 两种数据库
Database:
  Dialect: mysql
  # 是否在启动时自动创建/更新数据库表结构
  AutoMigrate: true
  # MySQL 数据库主机地址（若使用 SQLite3 则忽略）
  Host: 192.168.8.137
  # MySQL 数据库端口
  Port: 3306
  # 数据库用户名
  Username: root
  # 数据库密码
  Password: root_secure_password
  # 要连接的数据库名称
  Name: analytics
  # 仅当 Dialect 为 SQLite3 时生效，指定 SQLite 数据库文件路径
  SqliteFilePath: "./data/analytics.db"

# 认证相关配置
Auth:
  # JWT Token 在 HTTP Header 中的字段名（如 Authorization: Bearer <token> 中可自定义）
  TokenName: analytics_token
  # 用于签名 JWT Token 的密钥（建议使用高强度随机字符串）
  TokenSecret: login_secret
  # AES 加密用的密钥短语（必须为 16、24 或 32 字节，分别对应 AES-128/192/256）
  EncryptPassphrase: "cD4fG6hI8jK0lM2N"
  # Token 有效期（单位：秒），86400 = 24 小时
  TokenMaxAge: 86400

# Kubernetes 集成开关
K8S:
  # 是否启用 Kubernetes 模式（true 表示运行在 K8s 环境中，默认值为 true）
  Enable: true
  # NodeSelector 用于将 Pod 调度到带有指定标签的节点上。
  NodeSelector:
    cloud-used: "true"

    步骤四、访问悦数图分析控制台¶

    安装和配置完成后，您可通过以下两种方式访问悦数图分析控制台：

    方式一：临时端口转发（推荐测试使用）¶

    1. 临时端口转发到 analytics-server 端口：

      kubectl port-forward -n graph-system service/analytics-server 17006:7006 --address 0.0.0.0
      • 17006：本地临时端口，可自定义。
      • 7006：K8s 集群内的 Service 端口。

    2. 在浏览器中访问http://<YOUR_NODE_IP>:17006。<YOUR_NODE_IP>为 K8s 集群中任意节点的 IP 地址。例如，http://192.168.8.137:17006。

    方式二：通过 NodePort（推荐生产使用）¶

    安装 analytics-server 后，会自动为其创建 Service。默认 Service 类型为ClusterIP。如需 NodePort，可修改 Service 配置。操作如下：

    1. 编辑 Service 配置：

      kubectl edit service analytics-server -n graph-system

    2. 修改 Service 配置，将type修改为NodePort。示例配置如下：

      # analytics-server.yaml
spec:
  type: NodePort

    3. 查看 Service 详情获取 NodePort 端口：

      kubectl get service analytics-server -n graph-system

      返回：

      NAME                    TYPE       CLUSTER-IP      EXTERNAL-IP   PORT(S)          AGE
analytics-server        NodePort   10.102.64.200   <none>        7006:30310/TCP   19h
      • 30310为分配的 NodePort 端口。

    4. 在浏览器中访问http://<YOUR_NODE_IP>:30310，例如，http://192.168.8.137:30310。然后，显示悦数图分析控制台的欢迎页：

    参数名 描述 默认值
    replicaCount 部署的 Pod 数量，用于控制 Deployment 运行多少个实例以实现高可用或扩缩容。 1
    image.repository 要拉取的容器镜像仓库与名称，决定运行的应用来源。 reg.vesoft-inc.com/cloud-dev/analytics-api
    image.pullPolicy 镜像拉取策略，Always表示每次启动 Pod 都从仓库检查并拉取镜像。 Always

    nameOverride 覆盖 Chart 的基础名称，用于自定义生成资源名的前缀部分。 ""
    fullnameOverride 覆盖生成资源的完整名称，用于完全自定义资源命名。 ""
    serviceAccount.create 是否为该应用创建新的 ServiceAccount，用于绑定权限与身份。 true
    serviceAccount.annotations 为 ServiceAccount 添加自定义注解，用于记录元信息或与其他组件集成。 {}
    serviceAccount.name 指定使用的 ServiceAccount 名称，留空时由 chart 自动生成或使用默认名称。 ""

    podLabels 为 Pod 对象添加自定义标签，用于选择器匹配、分组统计或策略控制。 {}
    podSecurityContext Pod 级安全上下文设置。 {}

    service.type Service 类型：ClusterIP、NodePort、LoadBalancer。 ClusterIP
    service.port Service 暴露给集群内的服务端口，用于客户端连接该服务。 7006
    ingress.enabled 是否创建 Ingress 资源，通过 Ingress 控制器按域名与路径对外暴露 HTTP(S) 访问。 false

    ingress.annotations 为 Ingress 添加自定义注解，用于启用控制器特性或配置行为。 {}
